How fare is calculated assumed rates, same as the booking page, not real Ola or Uber prices

  1. Distance: the Haversine formula gives the straight-line km between pickup and drop (latitude and longitude). Multiply by 1.3 as a road estimate.
  2. Time: road km divided by an average speed of 25 km/h.
  3. Fare: (base + per-km rate x km + per-minute rate x minutes) x demand multiplier.
  4. Demand multiplier: 1 + 0.5 x (waiting riders divided by free drivers, minus 0.5), never below 1.0 or above 2.0. More riders than free drivers means a higher price.
  5. Minimum fare: the fare can't drop below the vehicle's minimum.
  6. Booking fee: a flat 5 rupees is added at the end.

The atomic claim why a driver can never be given to two riders

Two riders ask for the same driver at almost the same moment. If the system first looks ("is the driver free?") and then marks the driver taken a moment later, both riders can see "free" in the gap. The atomic way does the look and the mark as one step nobody can interrupt.

Careless: check, then set 
if driver is AVAILABLE:
    ...wait (network, database)...
    driver = OFFERED   // too late
Atomic: check and set as one step 
if driver is AVAILABLE:
    driver = OFFERED   // no gap
    return won
else:
    return blocked

The engine above uses the atomic form (its claim step). In production the same step is one Redis Lua script, which Redis runs without letting anything in between:

if redis.call('GET', KEYS[1]) == 'AVAILABLE' then
  redis.call('SET', KEYS[1], 'OFFERED', 'EX', 15)  -- lock expires in 15s
  return 1
else
  return 0
end
Press the button. Requests arrive at random moments over about 400 ms, and the careless version waits up to 4 ms between looking and marking, like a round trip to a database. It takes a moment to run.

What this demo is: many requests interleaving in the browser, which is the same race a server has when it reads from a database and writes back later. What it is not: separate CPU threads or a real Redis. For real parallel threads, run concurrency_test.js with Node. In one run on a 16-core computer it gave: careless 13 drivers double-assigned, atomic 0.
